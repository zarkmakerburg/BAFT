# ۲ — استفاده با x-ui و 3x-ui

[فهرست راهنما](README.md) · [English](../../en/guide/02-use-with-x-ui.md)

## چطور کار می‌کند

<div dir="ltr" align="left">

```text
user (in Iran)  ──►  Iran server :443  ══ BAFT tunnel ══►  outside server :443 (x-ui inbound)
                     Iran server :2053 ══ BAFT tunnel ══►  outside server :2053 (x-ui inbound)
```

</div>

برای هر **پورت عبوری**، سرور ایران روی همان پورت به‌صورت عمومی گوش می‌دهد و هر اتصال را از داخل تونل رمزنگاری‌شده به **همان پورت** روی سرور خارج می‌فرستد. x-ui تغییری نمی‌کند و inboundهایش تنظیمات، کلیدها و کاربرانشان را نگه می‌دارند.

## چهار قدم

1. **پورت‌ها را انتخاب کنید.** در x-ui پورت هر inboundی را که می‌خواهید از ایران در دسترس باشد یادداشت کنید. وقتی نصب‌کننده روی سرور خارج پورت‌ها را می‌پرسد، پورت‌هایی را که سرور الان روی آن‌ها گوش می‌دهد پیشنهاد می‌کند؛ آن‌هایی را که inbound x-ui هستند نگه دارید. در اسکریپت: `--ports 443,2053`.
2. **نصب و جفت کنید** ([نصب](01-install.md) را ببینید). نصب‌کننده پیش از جفت‌شدن مسیر ایران به خارج را تست می‌کند.
3. **روی سرور ایران بررسی کنید** که روی این پورت‌ها گوش می‌دهد (دستور پایین).
4. **لینک کاربران را عوض کنید.** در لینک یا اشتراک هر کاربر فقط آدرس سرور را به **IP سرور ایران** (یا دامنه‌ای که به آن اشاره می‌کند) تغییر دهید. پورت، UUID یا رمز، نوع انتقال، path، SNI و بقیه همان می‌مانند.

<div dir="ltr" align="left">

```bash
ss -ltn | grep -E ':(443|2053)\b'
```

</div>

نمونه:

<div dir="ltr" align="left">

```text
before:  vless://UUID@OUTSIDE_IP:443?type=ws&path=/abc&security=tls&sni=example.com#user
after:   vless://UUID@IRAN_IP:443?type=ws&path=/abc&security=tls&sni=example.com#user
```

</div>

در inboundهای TLS یا Reality، SNI و گواهی همان سرور خارج می‌مانند؛ فقط آدرسی که کلاینت به آن وصل می‌شود عوض می‌شود.

<a id="what-works"></a>

## چه چیزی کار می‌کند

فقط TCP:

- VLESS، VMess و Trojan روی **TCP، WebSocket، gRPC و HTTPUpgrade** (با یا بدون TLS و Reality).
- UDPای که **داخل** همین پروتکل‌ها حمل می‌شود (مثلاً DNS، تماس صوتی یا بازی از داخل VLESS/VMess/Trojan).
- هر سرویس TCP سادهٔ دیگر (وب‌سرور، SSH روی پورتی غیر از ۲۲ و مانند این‌ها).

<a id="what-does-not-work"></a>

## چه چیزی کار نمی‌کند

هر چیزی که بین کلاینت و سرور UDP خام لازم دارد: **Hysteria2، TUIC، WireGuard**، OpenVPN روی UDP، رلهٔ UDP در Shadowsocks ساده، و انتقال‌های KCP/mKCP و QUIC. بافت UDP را عبور نمی‌دهد.

## افزودن یا تغییر پورت‌ها بعداً

نصب‌کننده را روی سرور خارج دوباره اجرا کنید؛ پیش از هر تغییری برنامه را نشان می‌دهد. ببینید: [به‌روزرسانی، پشتیبان و حذف](05-update-backup-uninstall.md).

## نکته‌های مهم

- پورت‌های عبوری روی سرور ایران عمومی‌اند و بررسی نمی‌کنند چه کسی وصل می‌شود؛ مثل قبل، احراز هویت خود x-ui (UUID، رمز) از سرویس محافظت می‌کند.
- پورت‌های عبوری را در فایروال سرور ایران و اگر دیتاسنتر پنل فایروال دارد، در آن هم باز کنید.
- سرویس دیگری (مثلاً یک x-ui دوم) را روی همین پورت‌ها روی سرور ایران اجرا نکنید.
- اگر کاربران وصل می‌شوند ولی ترافیک بعد از چند کیلوبایت قطع می‌شود، احتمالاً دیتاسنتر ایرانی اتصال به خارج را روی آن پورت قطع می‌کند. با `sudo baft-net` تست کنید و پورت دیگری را امتحان کنید؛ ببینید [عیب‌یابی](06-troubleshooting.md#cut-after-few-kb).
