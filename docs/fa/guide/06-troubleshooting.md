# ۶ — عیب‌یابی

[فهرست راهنما](README.md) · [English](../../en/guide/06-troubleshooting.md)

روی سروری که مشکل دارد اول این‌ها را اجرا کنید:

<div dir="ltr" align="left">

```bash
baft doctor              # checks config, keys, service, release and reachability
baft status
journalctl -u baft -f    # live tunnel logs (Ctrl+C to stop)
```

</div>

وقتی کمک می‌خواهید، خروجی `baft doctor` و اگر خواسته شد، بستهٔ پشتیبانی (منوی `baft` ← ۱۰) را ضمیمه کنید. این‌ها محتوای ترافیک، کلید یا رمز ندارند، ولی پیش از انتشار یک بار نگاهشان کنید و هرگز کد جفت‌شدن یا رمز را منتشر نکنید.

## SSL پنل صادر نمی‌شود (پورت ۸۰ اشغال است، DNS)

Let's Encrypt هنگام صدور گواهی باید از طریق **پورت ۸۰** به سرور شما برسد.

- **پورت ۸۰ اشغال است**: با `ss -ltnp | grep ':80 '` ببینید چه چیزی از آن استفاده می‌کند. اغلب nginx، Apache یا یک inbound در x-ui/Xray روی پورت ۸۰ است. یک دقیقه متوقفش کنید، `sudo baft-panel` ← ۶ را اجرا کنید و بعد دوباره روشنش کنید.
- **پورت ۸۰ بسته است**: آن را در فایروال سرور (`ufw allow 80/tcp`) و در پنل فایروال ارائه‌دهنده باز کنید.
- **دامنه به این سرور اشاره نمی‌کند**: خروجی `dig +short panel.example.com` باید IP عمومی همین سرور باشد. اگر پشت Cloudflare هستید، هنگام صدور، پروکسی (ابر نارنجی) رکورد پنل را خاموش کنید یا به‌جای دامنه از IP استفاده کنید.
- **گواهی برای IP**: بدون دامنه کار می‌کند؛ کوتاه‌مدت (۶ روزه) است و خودکار تمدید می‌شود.

اگر باز هم صادر نشد، نصب‌کننده گواهی خودامضا پیشنهاد می‌کند. پنل با آن کار می‌کند، ولی افزودن سرور با SSH تا وقتی گواهی واقعی نصب نشده خاموش می‌ماند.

## گیت‌هاب از سرور ایران بسته است

دانلود از گیت‌هاب از داخل ایران اغلب شکست می‌خورد یا خیلی کند است.

- **سرور ایران را از سرور خارج نصب کنید**، با SSH (گزینهٔ نصب‌کننده روی سرور خارج، یا `--ir-ssh`). دانلود را سرور خارج انجام می‌دهد.
- یا از **بستهٔ آفلاین** استفاده کنید: `baft-offline-<version>.tar.gz` را روی دستگاهی که به گیت‌هاب دسترسی دارد دانلود کنید، به سرور ایران منتقل کنید و `sudo bash install.sh --offline . ...` را اجرا کنید ([نصب](01-install.md#offline-install) را ببینید).

## کد جفت‌شدن منقضی شده

کد `BAFTPAIR1:` فقط **۱۵ دقیقه** و فقط یک بار معتبر است. اگر سرور ایران گفت کد منقضی یا مصرف شده، نصب‌کننده را روی سرور خارج دوباره اجرا کنید: سرور خارجی که هنوز منتظر جفت‌شدن است کد تازه می‌گیرد. کد تازه را ظرف ۱۵ دقیقه روی سرور ایران وارد کنید. برای جفت‌کردن دوبارهٔ سرورهایی که قبلاً جفت شده‌اند از `--re-pair --yes` استفاده کنید (تا پایان جفت‌شدن، تونل قطع می‌شود). نصب سرور ایران با SSH نیاز به کپی دستی کد را از بین می‌برد.

<a id="cut-after-few-kb"></a>

## اتصال بعد از چند کیلوبایت قطع می‌شود

نشانه: کلاینت‌ها وصل می‌شوند ولی ترافیک می‌ایستد؛ صفحه‌های کوچک باز می‌شوند ولی دانلود گیر می‌کند؛ یا تست مسیر نصب‌کننده رد می‌شود.

بعضی دیتاسنترهای ایرانی اتصال TCP به خارج را روی بیشتر پورت‌ها بعد از چند کیلوبایت قطع می‌کنند (در یک مورد حدود ۸٫۷ کیلوبایت روی همهٔ پورت‌ها به‌جز ۲۲).

1. روی **سرور ایران** `sudo baft-net speed` را اجرا کنید. پیام *the transfer stopped after N bytes* قطع شدن را تأیید می‌کند.
2. `sudo baft-net port` را با IP سرور خارج و پورت بافت اجرا کنید.
3. برای بافت یا سرویس عبوری پورت دیگری امتحان کنید و دوباره تست کنید.
4. اگر همهٔ پورت‌ها قطع می‌شوند، مشکل از دیتاسنتر است؛ ارائه‌دهندهٔ ایرانی دیگری ممکن است رفتار متفاوتی داشته باشد.

## پنل باز نمی‌شود

- روشن است؟ `sudo baft-panel status` (گزینهٔ ۱). اگر خاموش است، `sudo baft-panel restart` و بعد `sudo baft-panel logs` را بخوانید.
- لینک درست است؟ `sudo baft-panel link` لینک کامل را با مسیر مخفی نشان می‌دهد؛ آدرس خالی بدون مسیر، پنل را باز نمی‌کند.
- فایروال: پورت پنل را در `ufw` (`ufw allow PORT/tcp`) و در فایروال ارائه‌دهنده باز کنید.
- `https://` یا `http://`: با گواهی، لینک `https://` است.
- گواهی منقضی شده: `sudo baft-panel renew`، یا `systemctl status baft-bcc-cert.timer` را بررسی کنید.
- رمز را فراموش کرده‌اید: `sudo baft-panel` ← ۳ ورود تازه می‌سازد.

## کاربران از طریق سرور ایران وصل نمی‌شوند

- روی سرور ایران، `ss -ltn` باید پورت عبوری را نشان دهد. اگر نشان نمی‌دهد، `baft status` و `journalctl -u baft -f` را ببینید.
- پورت باید در فایروال سرور ایران و فایروال دیتاسنتر باز باشد.
- پروتکل پشتیبانی می‌شود؟ پروتکل‌های مبتنی بر UDP (Hysteria2، TUIC، WireGuard) کار نمی‌کنند؛ ببینید [استفاده با x-ui](02-use-with-x-ui.md#what-does-not-work).
- در لینک فقط آدرس سرور باید عوض شود؛ پورت، SNI و بقیه مثل قبل می‌مانند.

## لاگ‌ها

<div dir="ltr" align="left">

```bash
journalctl -u baft -f              # tunnel, live
journalctl -u baft -n 200          # tunnel, last 200 lines
baft logs -n 200 -f                # the same through baft
sudo baft-panel logs               # panel
journalctl -u baft-agent -n 100    # agent (servers managed by the panel)
```

</div>

لاگ‌ها هرگز محتوای ترافیک کاربران را ندارند. با این حال پیش از اشتراک‌گذاری نگاهشان کنید و اگر خواستید IPها را حذف کنید.

## نصب‌کننده ادامه نمی‌دهد

- `BROKEN_INSTALL`: config معتبر نیست یا کلیدی گم شده؛ چیزی تغییر نکرده است. با `baft doctor` علتش را ببینید.
- «downgrade refused»: نسخه از نسخهٔ نصب‌شده قدیمی‌تر است؛ این محافظت در برابر حملهٔ بازگرداندن نسخه است.
- «verification failed»: نسخه با کلید ریشهٔ ثبت‌شده جور نیست. دورش نزنید؛ گزارشش کنید ([SECURITY.md](../../../SECURITY.md)).

</div>
