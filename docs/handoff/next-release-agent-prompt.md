# پرامپت برای agent بعدی: بردن BAFT تا release بعدی

تو روی مخزن `zarkmakerburg/BAFT` کار می‌کنی. مرجع اصلی issue **#67** (HQ Command Board) است. اول #67 را از آخر به اول بخوان، بعد این فایل‌ها را:
- `docs/release/p0-execution-plan.md` در PR #251 (برنامهٔ P0 و تصمیم‌های owner)
- `docs/handoff/server-tunnel-cards.md` در PR #253 (کار نیمه‌تمام UI)

## قانون‌های HQ (بدون استثنا)
1. **قبل از هر ادعا، شواهد بیاور:** خروجی تست، SHA و لینک CI. اگر چیزی را بررسی نکرده‌ای، بنویس «بررسی‌نشده».
2. **کارها کوچک باشند:** هر PR یک کار، همراه با تست، و به‌صورت draft. وقتی PR به PR دیگری وابسته است، آن را روی همان PR پایه بساز.
3. **merge، tag، امضا، release و deploy فقط با تأیید صریح HQ.** خودت approve یا merge نکن.
4. **به سرویس و تونل‌های کاربر دست نزن.** هر تغییری روی سرور فقط بعد از plan → تأیید اجرا شود. ترتیب آپدیت: BCC، بعد transport (`--role ir|ex`)، بعد agent (`--agent-only`). BCC با `--bcc-only`.
5. **گزارش‌ها فارسی باشند و در #67 ثبت شوند:** چه کردی، شواهد، و چه چیزی باز مانده.
6. **روی PR دیگران push نکن.** یافته‌هایت را به‌صورت کامنت بنویس، با مسیر بازتولید و پیشنهاد اصلاح.
7. **تست را skip یا disable نکن.** برای راه انداختن CI هم commit خالی نزن.

## ترتیب کار تا release بعدی
1. **سبز کردن پایه:** در #252، کارت «BCC Backups» در `web/bcc-operations-v3.js` (`routes`) route ندارد و `aurora-card-routing` را قرمز می‌کند. اصلاح را با کامنت پیشنهاد بده، یا اگر owner #252 اجازه داد، اعمالش کن. CI #252 و #253 روی head دقیق باید سبز شود.
2. **e2e واقعی agent↔BCC:** یک agent واقعی را به یک BCC واقعی (روی loopback، با catalog امضاشدهٔ محلی از `scripts/release/local_release.sh`) وصل کن و نشان بده:
   - نشان `verified` بعد از گزارش agent ظاهر می‌شود؛
   - binary دست‌کاری‌شده `mismatch` نشان می‌دهد؛
   - گزارش کهنه بعد از ۱۵ دقیقه `unknown` می‌شود.
   این را به `tests/e2e/` اضافه کن.
3. **ادامهٔ #253** طبق فهرست handoff:
   1. ترجمهٔ نام وضعیت‌ها (`phaseTr`)؛
   2. تاریخچهٔ چرخش گواهی در کارت تونل؛
   3. باز شدن کارت از ردیف‌های داشبورد؛
   4. deep link `#servers/<id>[/<tunnel>]`؛
   5. آزمون مرورگر در هر دو زبان و عرض موبایل (`web/qa/fixture` + Playwright با `/opt/pw-browsers/chromium`).
4. **Update All از BCC (P0-UUM-03/04):**
   - restart هماهنگِ تک‌تک instanceها از سمت BCC (تصمیم owner)؛
   - plan → تأیید → اجرا، با پیشرفت هر سرور؛
   - بکاپ تازه قبل از آپدیت BCC.
   دکمهٔ «به‌روزرسانی نسخه» کارت سرور به همین وصل شود. تا وقتی این مسیر سبز نشده، مسیر deploy تازه نساز.
5. **wizard تونل دستی:** ۵ ورودی با انتخاب engine در قدم اول (تصمیم owner). Smart Auto بعد از آن.
6. **اعلان release** در BCC و منوی CLI، و **parity** بین CLI، Classic و Aurora: برای هر عملیات جدولی بساز که نشان دهد در کدام رابط هست و کدام نیست، و تست contract بنویس.
7. **آمادگی release:**
   - changelog؛
   - docs فارسی و انگلیسی؛
   - اجرای کامل `tests/e2e/installer_faults.sh`؛
   - یک release محلی امضاشده و آپدیت از release قبلی روی آزمایشگاه (IR و EX).
   بعد گزارش «آماده برای تأیید HQ» را در #67 بگذار و **منتظر تأیید بمان**.
