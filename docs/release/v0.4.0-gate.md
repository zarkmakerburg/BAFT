## 1. The `operational ingress v1` gate

Workflow: `.github/workflows/operational-ingress-v1.yml` (job
`operational-ingress-v1`). Checker: `tests/release/opgate/`. Manifest:
`tests/release/opgate/manifest.v1.json`.

What it enforces, on the exact commit under test (`pull_request.head.sha`, or
`github.sha`; the job aborts if `git rev-parse HEAD` differs):

1. The manifest SHA-256 is pinned in the workflow (`MANIFEST_SHA256`). Changing the required test set needs a reviewed change to both.
2. Every manifest test is compiled and run inside a disposable private network namespace (`run_lab.sh`) and emitted as `test2json`.
3. `opgate` decides the verdict, never the test runner exit code. A manifest entry is green only if its package-qualified top-level test has a real `PASS` result with **zero SKIP** (any subtest too), zero FAIL, and no package FAIL. Missing, RUN-only, skipped, failed, truncated, empty, non-JSON, oversized-line or wrong-SHA input is red.
4. The manifest must cover every stage of the full path (the checker rejects a manifest that drops one): reviewed BCC Wizard API -> normal signed Agent -> held lease -> real listener/nft -> client TCP bytes -> authenticated HTTPS receipt (Agent -> BCC) -> BCC verified config/card, plus the end-to-end test, wrong node/plan/hash/port/lease/generation/enrollment/TLS, replay/expiry, active/stopped/v4-v6-sibling foreign services, partial Add/Remove + restart + Retire, sibling tunnels and multi-EX on one IR, and CLI pairing with inaccessible BCC and re-pair.
5. Test names must start with `TestOperationalIngressV1Gate_`. The existing blocked-path tests (`TestOperationalIngressSignedPollReportsBlockedReceiptAndNeverUsesLAB`, etc.) deliberately do not count: they prove refusal, not success.

Current result (executed locally on `512be47` plus this change): running
`go test -json -run '^TestOperationalIngressV1Gate_'` over the four internal
packages and feeding the output to `opgate` printed `GATE RED: 0/28 required
operational ingress v1 tests passed`, exit 1. None of the 28 tests exist yet;
`./tests/e2e/operational` does not exist. The gate turns green only when Alpha,
Delta, Beta and Gamma land the named tests and they pass without skipping.
The netns runner itself (`run_lab.sh`) could not be executed in the authoring
sandbox (no `ip`); it has not been exercised on GitHub Actions either.

Update (branch `claude/v040-e2e`): all 28 tests now exist as real tests (no
stubs). Fixed-path policy: the operational path reads
`/etc/baft/ingress/managed-node.json` and scans systemd unit roots, but this
gate must not touch the host. `tests/e2e/operational/oplab` therefore
re-executes each test binary in place (no parent process may remain in the
network namespace: the product's inventory requires the test process to be
the only holder) inside a private mount namespace whose `/etc` and
`/usr/lib/systemd/system` are tmpfs copies. In gate mode
(`BAFT_OPERATIONAL_INGRESS_V1=1`) a missing prerequisite FAILS; outside gate
mode the privileged tests skip. The tests were executed in a Linux container
LAB (`tests/e2e/operational/labinit` is a stand-in PID 1 named `systemd` that
gives each package a private netns; nft and iproute2 from Ubuntu noble), NOT
on GitHub Actions and NOT on a real systemd host. EX/IR tunnel engines are
protocol fixtures in the Wizard flow (acknowledged through the real signed-job
HTTP API); the tunnel target is a loopback echo. Everything on the IR side
(Agent, signed jobs, held lease, listener, nft, receipt, BCC probe, card) is
the real code.

Isolation rules baked into the gate: the runner creates no LAB sentinel
(`/baft-policy-lab` or otherwise) on the host and refuses to run when
`BAFT_ISOLATED_POLICY_LAB` is set. Linux UID 0 is never treated as an
isolated root filesystem; tests that need a disposable scratch-container
rootfs (installed policy provisioning) are not eligible for this runner and
remain in `tests/e2e/managed_ingress_policy_lab.sh`.

Fixed defects in the older Gamma checks:

- `tests/e2e/gamma_policy_log_assert.sh` only looked for `--- SKIP/FAIL` at column 0, so a skipped (indented) subtest under a PASSing parent was accepted. It now matches indented and `/subtest` results; fixtures in `gamma_policy_log_assert_fixture_test.sh` cover subtest SKIP, CRLF, an oversized whitespace line followed by SKIP, and a missing family (RED reproduced before the fix). It still derives its required set from the log itself, which is why the new gate uses a pinned manifest instead.
- The Go checker parses exact name tokens (`TestX` never satisfies `TestXExtra`; the `(0.01s)` suffix is never part of a name), tolerates CRLF and trailing whitespace, and reads logs with a bounded reader that errors on oversized lines (the `bufio.Scanner` stop-silently failure mode would otherwise hide a later SKIP).
- `TestGammaBCCReceiverWhitespaceBoundary` pins the receipt receiver at 4096 accepted / 4097 refused, so oversized-whitespace refusal is a size decision and not an accident of trailing-whitespace parsing. Receipt direction (enrolled Agent POSTs to BCC over certificate-validated HTTPS, no redirect, no plaintext) was already correct in `gamma_enrolled_https_receipt_v1_test.go`; no change needed.

Not done here (outside the allowed paths, needs the owner):

- `scripts/release/accept.sh` requires an optional workflow only if its file exists at the tag, and does not know `operational-ingress-v1.yml`. It must require the `operational-ingress-v1` run/job at the tag SHA unconditionally, or the tag gate can still be passed without this one.
- GitHub branch protection/ruleset on the QA branch and `main` must list `operational-ingress-v1` as a required status check. A workflow file cannot make itself required.

## 4. How to turn the gate green

1. Alpha/Delta/Beta/Gamma land the 28 named tests (see the manifest for package and name per stage). A test that cannot run in the netns must not skip: make it fail until the prerequisite exists.
2. Do not edit the manifest to drop or rename entries without a reviewed change to `MANIFEST_SHA256`.
3. Owner: make `operational-ingress-v1` a required status check and extend `scripts/release/accept.sh` to require it at the tag SHA.
4. Run it on the exact candidate SHA; keep the uploaded `opv1-report.json` as release evidence.
