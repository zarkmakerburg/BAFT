# دستورالعمل ادامه‌ی کار v0.4.0 (تحویل به ایجنت بعدی)

آخرین به‌روزرسانی: 2026-10-27، روی commit `727247b` در شاخه‌ی `claude/v040-integration`.

این سند برای ایجنتی نوشته شده که کار را از اینجا ادامه می‌دهد. اول کل سند را بخوانید. بعد [#67](https://github.com/zarkmakerburg/BAFT/issues/67) را از آخر به اول مرور کنید، چون همه‌ی شواهد با SHA و ساعت آنجا ثبت شده‌اند.

## ۱. قواعد ثابت مالک (تغییرناپذیر)

- **هیچ merge به main، tag یا release بدون «برو» ی صریح مالک انجام نمی‌شود.** امضای آفلاین هم فقط کار خود مالک است.
- هیچ ادعای «تست پاس شد» بدون شاهد و SHA ِ دقیق پذیرفته نیست.
- رفتار fail-closed تضعیف نمی‌شود. هیچ تستی skip یا حذف نمی‌شود. هیچ empty commit ای push نمی‌شود.
- گزارش‌ها برای مالک **به فارسی** نوشته می‌شوند. نام‌های فنی و جدول‌ها می‌توانند انگلیسی باشند.
- مالک تصمیم گرفته که نتایج روی سرورهای واقعی‌ای که خودش داده، شاهد محیط واقعی حساب شوند. برچسب «LAB» لازم نیست.
- shared multiplex فعلاً فقط از CLI (`--join`) پشتیبانی می‌شود. مدیریت آن از BCC به نسخه‌ی بعد رفته است (در نقشه‌ی راه ثبت شده).
- failover بین EXها (`baft failover`) با تأیید مالک جزو v0.4.0 است.
- DNS failover رایگان است (Cloudflare DNS API) و **اختیاری**. کاربر دامنه و token می‌دهد و زیردامنه را انتخاب می‌کند؛ اگر انتخاب نکند تصادفی ساخته می‌شود. اگر دامنه ندهد، سیستم عادی بدون تغییر کار می‌کند.
- هیچ رمز، token یا کد pairing (BAFTPAIR1/BAFTREPLY1) نباید در لاگ، commit یا کامنت بماند.

## ۴. کارهای باقی‌مانده (به ترتیب پیشنهادی)

1. **تست واقعی DNS failover روی Cloudflare.** مالک باید token (Zone:Read + DNS:Edit) و دامنه را بدهد. connector ِ Cloudflare در جلسه‌ی ابری به خاطر سیاست شبکه (proxy 403) وصل نمی‌شود. اجرا روی EX-2:
   `echo TOKEN | baft-dev dns-failover setup --domain DOMAIN --target ir-a=193.201.66.33 --target ir-b=194.110.24.20 --probe-port PORT`
   بعد یک IR را خاموش کنید و ببینید رکوردش حذف و بعد برگردانده می‌شود.
2. **failover روی مسیر «باز ولی قطع پس از ۸KB» در host واقعی.** تست واحد دارد، اما در تست واقعی فقط حالت «تونل مرده» دیده شده است. یک پیشنهاد: probe را روی A به EX-1 با carried port ِ echo بفرستید.
3. **IR روی مسیر محدود خارج می‌شود** (`node stopped: shard ...: connection reset`) و systemd آن را restart می‌کند. باید بررسی شود که آیا این رفتار درست است یا بهتر است IR زنده بماند و فقط گزارش دهد.
4. **وصل کردن mesh و failover به installer یا BCC.** الان تونل دوم با `baft-pair` و unit ِ دستی ساخته می‌شود و `baft failover install` جدا اجرا می‌شود.
5. **ردیف‌های BLOCKED ِ readiness** (۳، ۵، ۶، ۷، ۱۰، ۱۱، ۱۳، ۱۵ تا ۱۸). ردیف ۳ (بسته بودن SSH از EX به IR) با همین سرورها قابل تست است.
6. **اجرای دوباره‌ی هر ۸ gate روی SHA ِ نهایی**، ثبت در #67 و سند gate.
7. **گزارش نهایی فارسی به مالک.** release فقط با «برو» ی مالک و امضای آفلاین خود او.
