## Draft release notes and upgrade procedure

This increment supplies safety fixes and executable regression tests, not a deployable v0.4.0 release. The changelog lists changes on the development branch. Keep external engines and the separate floating ingress wizard unavailable for operational actions until their backends are admitted.

Before an upgrade: identify each target node and role, record installed component versions and ownership, export encrypted BCC state plus owned tunnel/unit/config/certificate data, retain the currently trusted signed binaries and verify an actual restore in isolation. Protect SSH and unrelated services; 3X-UI retains all UUID/subscription ownership. No production backup or restore drill has been performed by this development increment.

After P0 completion: run all required workflows on the final main commit, independently build and verify provenance, create `v0.4.0` only on that accepted commit, produce signatures using the existing trusted certified signer, publish and verify every artifact and checksum with `scripts/release/accept.sh`. Never rewrite an existing published tag. A tag query during this run found no `v0.4.0` tag.

Deploy one verified node at a time only after those gates pass. Verify BAFT health, real client traffic, protected legacy listener, management access and unrelated service preservation. Stop and restore the verified previous binaries/configuration on regression. This run did not identify a complete authenticated production SSH inventory, did not alter operational hosts and did not claim a production backup.

Next execution order: durable ingress/agent lifecycle and integration, complete command console/capability inventory, remaining SSL/network/BCC P0s, isolated full-system acceptance, exact-SHA CI and trusted signing, then canary deployment with verified rollback.
