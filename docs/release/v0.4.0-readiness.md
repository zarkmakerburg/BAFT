## Readiness matrix

### Isolated listener increment (2026-10-20)

The development branch now includes a manual foreground `baft ingress run` TCP forwarder. It accepts literal addresses only, requires a loopback target, bounds concurrent clients and dial time, preserves both TCP half-close directions, releases sockets on cancellation, and refuses SSH/legacy port 2053 as endpoints. It does not acquire a BCC reservation or authorize an agent job; it does not manage systemd, firewall policy, audit, or reboot reconciliation. A successful local bind is not evidence of public reachability. Keep the installer and BCC operational controls disabled until the generation-bound lifecycle and rollback are implemented and accepted. No production traffic has been routed through this increment.

## Draft release notes and upgrade procedure

This increment supplies safety fixes and executable regression tests, not a deployable v0.4.0 release. The changelog lists changes on the development branch. Keep external engines and the separate floating ingress wizard unavailable for operational actions until their backends are admitted.

Before an upgrade: identify each target node and role, record installed component versions and ownership, export encrypted BCC state plus owned tunnel/unit/config/certificate data, retain the currently trusted signed binaries and verify an actual restore in isolation. Protect SSH and unrelated services; 3X-UI retains all UUID/subscription ownership. Read-only Arno inventory verified the expected `template` hostname, BAFT 0.3.7, active BAFT/Agent services and an existing socat-owned 2053 listener (not an ingress resource to adopt or remove). Goldapp Main closed SSH before inventory; its health is unverified. No production backup or restore drill has been performed by this development increment.

After P0 completion: run all required workflows on the final main commit, independently build and verify provenance, create `v0.4.0` only on that accepted commit, produce signatures using the existing trusted certified signer, publish and verify every artifact and checksum with `scripts/release/accept.sh`. Never rewrite an existing published tag. A tag query during this run found no `v0.4.0` tag.

Deploy one verified node at a time only after those gates pass. Verify BAFT health, real client traffic, protected legacy listener, management access and unrelated service preservation. Stop and restore the verified previous binaries/configuration on regression. This run verified Arno read-only but did not complete the production inventory, alter operational hosts or create a production backup.

Next execution order: generation-aware ingress agent lifecycle and wizard integration, complete command capability inventory, remaining SSL/network/BCC P0s, isolated full-system acceptance, exact-SHA CI and trusted signing, then canary deployment with verified rollback.
