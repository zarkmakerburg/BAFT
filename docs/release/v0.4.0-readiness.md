## Cross-process lifecycle continuation (2026-10-23)

A second deterministic RED regression paused CommitIR immediately before its service restart, after committing files and journal state. Another Manager completed Rollback; resuming the first restart then incorrectly reported commit success against rolled-back durable state. All seven top-level tunnel mutators and nine rotation entrypoints now hold one shared per-instance process flock across preflight, file changes, service actions and private rollback. Contention returns `ErrLifecycleBusy` before changing transaction/service state; callers must reconcile or submit a later operation rather than assuming success.

The persistent lock inode is never unlinked on release. It must be an empty, private, owned, single-link regular file; symlinks, FIFOs, foreign contents and unsafe permissions are refused. The lock/path/directory identity is rechecked after acquisition. This coordinates cooperating CLI/Agent processes in the trusted installer-provisioned StateDir; it is not live-resource ownership or reboot adoption. The mutator must use the lock-owning effective UID; an incompatible owner fails closed. Non-Unix mutation fails closed because this process lock is unavailable. Private helpers avoid recursive acquisition; read-only Inspect/Observe/Health/RotationState do not provide atomic cross-process snapshots.

The original commit/rollback regression passed 20 repetitions. Whole tunnelnode race tests and three focused lifecycle/process/unsafe-file/rotation race repetitions passed; tests also assert that every mutation entry refuses a held lock without reaching the service manager or creating transaction state. Full combined Linux `go test ./... -timeout=15m`, focused vet, diff check and independent review passed. Darwin/arm64 CLI cross-compilation passed with CGO disabled; this is not macOS runtime acceptance. Exact-SHA hosted verification remains required for this increment.

## Concurrent standalone admission continuation (2026-10-23)

A deterministic regression held two independent same-instance Managers after their existing-state checks: both previously admitted distinct transactions and overwrote the active owner. Admission now claims a private active marker with exclusive file creation, fsyncs it and its parent, then creates the winning transaction stage. Losers cannot overwrite the marker or leave an unowned stage. Partial/error claims are retained for reconciliation. Tests cover the original two-manager interleaving, separate-process contention, empty/partial/foreign/symlink markers and private file mode.

This marker protects new-transaction admission only; the subsequent lifecycle continuation above adds whole-operation process locking. A leftover active marker still blocks new admission even when its transaction is Finalized or RolledBack; it requires reconciliation rather than implicit replacement. Existing terminal transactions whose active markers were successfully cleared still permit new admission. This conservative recovery boundary is covered explicitly and is not automatic restart recovery.

Focused interleaving/marker/terminal tests passed 100 repetitions; process/interleaving/marker/terminal race tests passed three repetitions; the full tunnelnode race suite, full Linux suite, focused vet and independent review passed. Exact-SHA hosted checks remain required for the new admission increment.

The development branch now includes a manual foreground `baft ingress run` TCP forwarder.
