# v0.4.0 independent adversarial security review

Base: `origin/claude/v040-integration` (7593900), diff `v0.3.7..HEAD`.
Branch: `claude/v040-secreview`. Reviewer did not write the code under review.
Method: symbol and caller driven reading, concrete exploit construction, proof by
failing Go test or shell reproduction where feasible.

## Result

No CRITICAL or HIGH finding. Two MEDIUM findings were fixed with regression
tests (RED then GREEN). Remaining findings are LOW / residual and documented
below. No check was weakened.

## Checked and found sound (no finding)

(1) Authority chain. `agentjob.VerifiedJob` has unexported fields, only
`VerifyAdmitted` constructs a valid one, `Job()` returns a deep copy.
`MintLease` re-checks job vs command (id, node, action, exact window), held OS
flock, claim, pinned installed policy, recorded intent and lifecycle state, and
persists `Leased[action]=jobID` (fsync + rename) before returning a lease.
Apply requires APPLYING, Retire may run from APPLYING/NEEDS_RECONCILIATION.
Replay of a consumed job returns `ErrLeaseReplay`. An Apply intent is immutable;
re-apply on the same binding is refused. Seen ledger retention (7 days) exceeds
`MaxLifetime + ClockSkew`. `publicIngressOperational` routes only
`ingress_protocol=1` to the real path, never to the LAB executor; panics and
cancellation after effects record NEEDS_RECONCILIATION with a detached context.
Wrong node, other-node binding, expired window, generation drift, unenrolled
signer and closed guard are covered by existing tests (they run without the
LAB policy).

(2) Executor. Every effect re-checks the lease, installed policy, execution pin
and a fresh numeric-port kernel inventory (`socketEvidenceAtEffect`,
`checkInstall`, `checkRemove`). `reconcileStoppedRetire` requires complete
coverage, journalled RetireIntent with identical owner/port/handle, a
process-local stopped record bound to this Runtime/backend/chain handle and a
non-zero closed inode absent from the kernel table; a foreign LISTEN is never
adopted, and only the exact-handle nft rule of this owner is removed.
Journal/policy directories use openat/`O_NOFOLLOW`/`os.Root`, 0700/0600, uid and
nlink checks, `RENAME_NOREPLACE`.
Probe responder: echo is the identical 54-byte frame (no amplification, TCP so
source not spoofable), limited probes are dropped and never reach the target,
peek is bounded to 50 ms total, bytes are forwarded unmodified and first.

(3) `parseSystemdListenStream`: `%t/`-prefixed and `@name` values are accepted
only when literal, unquoted and colon-free (abstract names must not be pure
digits); every other specifier, backslash continuation, service name, quoting,
empty name, `@80`, `vsock:`, bare IPv6 and hostnames fail closed as
INCOMPLETE. Masked (symlink) units, orphan `.d` directories, group/other
writable files and in-flight modification all fail closed. Cannot hide a TCP
port claim with these forms.

(4) BCC gate. Capabilities are recorded only after `authorizedLocked` bearer
verification, strictly parsed (one header, <=8 tokens, `[a-z0-9-]`), keyed to the
authenticated node, cleared when absent, and the gate additionally needs a
non-revoked enrolled IR node, a heartbeat younger than 2 minutes and a role of
worker/master. An agent can only open the gate for its own IR node; there is no
flag or setter. Job signing re-derives params from the persisted reviewed
command (`signableOperationalIngress`) and refuses drift. Receipt endpoint:
HTTPS required, 16 KiB cap, exact-case field names, duplicate/unknown/null
rejection, token must authenticate `Binding.NodeID`, command/binding must equal
the stored one, one receipt per job (conflicting replay refused), cross-node and
lifetime checks. All new ingress admin endpoints use `s.admin`. Dashboard
renders agent-controlled strings via `textContent`/`esc`.

(5) Helper: run against real `nft` in a network namespace: create, marker,
rule-present refusal (exit 3), empty removal. JSON is matched with `grep -E`, but
every destructive step has a second guard (`nft delete chain` fails with EBUSY on
a non-empty chain; the layout and handle must match). No eval, markers parse only
`[0-9]+`, temp file is `mktemp` beside the marker in a 0700 root directory,
`mv -f` replaces a symlink rather than following it.

(6) Tunnelnode / carrier. Scoped instance IDs are regex validated before use in
paths; foreign config/unit/marker refuse; claim reuse requires an exact
`instance\n` claim file plus an owned, unchanged namespace and a config that
already binds that port. `carrierPeerPath` never loosens verification: an
unreadable or empty fallback CA is an error, `Clone()` preserves the TLS
settings, and an unset fallback CA deliberately inherits the primary pool
(not a silent insecure fallback).

## Residual risk

1. Readiness (finding 4) is self-attested plus an unauthenticated echo; do not
   treat the config card as proof that BAFT owns the port.
2. Operational Apply/Retire correctness rests on the LAB-only paths that could not
   be run here; the fail-closed design was verified by reading, not by execution.
3. Immutable-job design means a transient "blocked" receipt permanently consumes
   the Apply job identity at BCC (operator re-stage required): availability, not
   safety.
4. Receipt endpoint requires `r.TLS != nil`; deployments terminating TLS at a
   reverse proxy will never record receipts (fails closed).
5. Private-range IR addresses are probed (finding 3).
