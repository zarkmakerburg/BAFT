# LAB سرورهای واقعی (ایران ↔ خارج)

این LAB مسیر محصول v0.5.0 را روی **دو سرور واقعی تست** اجرا می‌کند: یک سرور در ایران و یک سرور در خارج، روی اینترنت واقعی. LAB دومیزبانهٔ CI فقط دو ماشین مجازی روی یک runner است و این مسیر را اثبات نمی‌کند. شواهد این دو همیشه جدا گزارش می‌شوند.

- اسکریپت: `tests/e2e/real_hosts.sh`
- workflow: `.github/workflows/real-hosts.yml` (Actions ← Real-hosts LAB ← Run workflow)

## پیش‌نیاز سرورها

| مورد | سرور ایران | سرور خارج |
|---|---|---|
| سیستم‌عامل | Ubuntu 22.04 یا 24.04، x86_64، systemd | همان |
| کاربر | root، یا کاربری با `sudo` بدون رمز | همان |
| BAFT نصب‌شده | نباید باشد | نباید باشد |
| کاربر واقعی | نباید داشته باشد (فقط تست) | نباید داشته باشد |
| پورت‌های ورودی باز در فایروال ارائه‌دهنده | SSH و پورت کلاینت (پیش‌فرض 18610) | SSH، پورت BCC (پیش‌فرض 18300)، پورت mirror (18301) و پورت‌های کاندید (پیش‌فرض 443، 8443 و 2053) |

## تنظیم Secrets مخزن

در GitHub: Settings ← Secrets and variables ← Actions ← New repository secret.

| نام | مقدار | اجباری |
|---|---|---|
| `BAFT_IR_HOST` | IPv4 عمومی سرور ایران | بله |
| `BAFT_EX_HOST` | IPv4 عمومی سرور خارج | بله |
| `BAFT_SSH_KEY` | کلید خصوصی SSH که روی هر دو سرور پذیرفته می‌شود (کل متن فایل) | بله |
| `BAFT_SSH_USER` | نام کاربر (پیش‌فرض `root`) | خیر |
| `BAFT_SSH_PORT` | پورت SSH، یکسان روی هر دو سرور (پیش‌فرض 22) | خیر |
| `BAFT_SSH_KNOWN_HOSTS` | خروجی دستور زیر، برای pin کردن کلید میزبان (توصیه می‌شود) | خیر |

یک کلید مخصوص همین تست بسازید و کلید عمومی آن را روی هر دو سرور اضافه کنید:

<div dir="ltr" align="left">

```bash
ssh-keygen -t ed25519 -N '' -C baft-real-hosts -f baft-real-hosts
ssh-copy-id -i baft-real-hosts.pub root@IR_IP
ssh-copy-id -i baft-real-hosts.pub root@EX_IP
ssh-keyscan -t ed25519 IR_IP EX_IP   # output -> BAFT_SSH_KNOWN_HOSTS
```

</div>

محتوای فایل `baft-real-hosts` (بدون `.pub`) در `BAFT_SSH_KEY` قرار می‌گیرد. بعد از پایان تست‌ها کلید عمومی را از سرورها حذف کنید و Secretها را پاک کنید.

## اجرا

1. **preflight** (پیش‌فرض و فقط‌خواندنی): هیچ چیزی را روی سرورها تغییر نمی‌دهد. این موارد را بررسی و گزارش می‌کند:
   - رسیدن SSH: مستقیم، یا اگر runner به سرور ایران نرسد، از طریق سرور خارج؛
   - سیستم‌عامل، kernel و systemd؛
   - nft، و اینکه BAFT از قبل نصب نشده باشد؛
   - آزاد بودن پورت‌های برنامه‌ریزی‌شده؛
   - وجود Xray، 3X-UI، nginx، HAProxy یا Docker؛
   - اتصال TCP از ایران به پورت‌های BCC و کاندید روی سرور خارج.
2. **full**: پس از preflight، این مسیر را اجرا می‌کند:
   - نصب BAFT از release امضاشدهٔ همین commit؛
   - تست اتصال (FULL_DATA)؛
   - انتخاب خودکار مسیر، Plan بازبینی‌شده با تأیید پورت و Deploy؛
   - Listener و قانون nft متعلق به BAFT، و Ready با probe مستقل BCC؛
   - ترافیک واقعی کلاینت؛
   - Restart هر دو agent؛
   - **Firewall Drop**: پورت عمومی مسدود می‌شود و BCC نباید Ready گزارش کند؛
   - قطع ۲۰ ثانیه‌ای مسیر تونل و بازیابی؛
   - **Reboot** سرور ایران (اختیاری با گزینهٔ `reboot`)؛
   - Decommission دقیق؛
   - Uninstall کامل.

   در پایان، حتی پس از شکست، همهٔ اثرات اجرا (BAFT، BCC، CA موقت و جدول‌های nft تست) پاک می‌شوند و باقی‌ماندهٔ احتمالی گزارش می‌شود.

خلاصهٔ اندازه‌گیری‌ها در Summary اجرا و در artifact `real-hosts-summary-*` ذخیره می‌شود. IPها در summary ثبت نمی‌شوند و در لاگ GitHub ماسک می‌شوند.

## دامنهٔ ادعا

- PASS این LAB یعنی مسیر محصول روی همین دو سرور، همین شبکه و همین SHA کار کرده است. به SHA دیگری یا شبکهٔ دیگری تعمیم داده نمی‌شود.
- self-test همین اسکریپت در هر اجرای LAB دومیزبانه (`two-host (real-hosts-selftest)`) روی دو ماشین مجازی اجرا می‌شود. این self-test درستی اسکریپت را اثبات می‌کند، نه مسیر ایران↔خارج را.
