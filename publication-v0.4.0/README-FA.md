# بارگذاری فایل‌های عمومی BAFT v0.4.0 از مک

**امضا انجام و تأیید شده است؛ دیگر به `release.key` یا هیچ کلید خصوصی نیاز نداریم.** هر ۱۰ فایل با منبع تأییدشدهٔ `9c32ba369fe2be2c549f2878d1de5dbf092c8f64` برابرند و بستهٔ آفلاین در دو ساخت، دقیقاً یکسان بوده است.

در GitHub یک **Draft** برای `v0.4.0` ساخته شده، اما بارگذاری از محیط ابری با خطای `401 Bad credentials` متوقف شده است. انتشار نهایی هنوز انجام نشده است. این مرحله فقط ۱۸ فایل عمومیِ آماده را از مک شما به همان پیش‌نویس منتقل می‌کند.

۱. اینترنت مک وصل باشد. GitHub CLI با نام `gh` باید نصب باشد و با حسابی وارد شده باشید که روی `zarkmakerburg/BAFT` مجوز نوشتن Release دارد؛ برای توکن محدود، مجوز مخزن `Contents: write` لازم است. ورود را با روش معمول خود `gh` روی مک انجام دهید؛ توکن یا رمز را در گفتگو نفرستید.

۲. **دستور دانلود، بررسی هش و اجرای ابزار بارگذاری را ایجنت در همین گفتگو با لینک ثابت ارائه می‌کند.** همان دستور را یک‌جا در Terminal اجرا کنید. ابزار بارگذاری به کلید امضای BAFT دسترسی لازم ندارد و فقط فایل‌های عمومی تعیین‌شده را روی Draft می‌فرستد؛ انتشار نهایی را انجام نمی‌دهد.

۳. پس از پایان، خروجی ابزار را در همین گفتگو بفرستید. ایجنت فایل‌های GitHub را مستقل دانلود و بررسی می‌کند، سپس انتشار را نهایی و آزمون پذیرش assetهای منتشرشده را اجرا می‌کند. رسید بارگذاری به‌تنهایی جای بررسی امضا و پذیرش انتشار را نمی‌گیرد.

کلید خصوصی را وارد پوشهٔ تحویل نکنید و ارسال نکنید. این کار Deploy نیست، میزبان‌های production را تغییر نمی‌دهد و به معنی بسته‌شدن Issue #269 نیست.
