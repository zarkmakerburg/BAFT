# BAFT v0.5.0

## فارسی

این نسخه نرم‌افزار پژوهشی است و پذیرش آن با LAB بازتولیدپذیر انجام شده است. برای اولین بار، مسیر محصول روی یک جفت سرور واقعی در ایران و خارج، روی اینترنت واقعی، هم آزموده شده است. این شواهد فقط همان سرورها، همان شبکه و همان SHA را پوشش می‌دهند؛ تضمین دسترس‌پذیری یا آمادگی production نیستند.

### تغییرهای اصلی

- **ساخت تونل با راهنما و به‌صورت زنده:**
  - «+ تونل جدید» در Command Center تونل واقعی را در پنج گام می‌سازد: سرورها، سرویس، تست اتصال، بازبینی و Deploy.
  - فقط وقتی «انجام شد» می‌گوید که تونل فعال و پورت عمومی آن توسط خود BCC تأیید شده باشد.
- **تست اتصال:**
  - تست امضاشدهٔ مسیر بین دو سرور روی پورت‌های انتخابی، با تخمین سرعت.
  - جریان‌های تست اکنون داخل TLS 1.3 با ClientHello شبیه مرورگر و بدون SNI اجرا می‌شوند و امضای ثابتی روی سیم ندارند. این حالت فقط وقتی فعال است که هر دو agent آن را پشتیبانی کنند.
- **حالت امن میزبان (اختیاری، `--enable-host-ingress`):**
  - BAFT پورت عمومی ایران را روی سرور معمولی باز می‌کند.
  - پیش از باز کردن پورت، پورتی را که در اختیار برنامهٔ دیگری، 3X-UI/Xray، nginx، HAProxy یا Docker است، رد می‌کند.
  - فقط listener و قانون خودش را در chain خودش می‌سازد و هنگام Decommission دقیقاً همان‌ها را حذف می‌کند.
- **بازیابی پس از Restart و Reboot:** پیش‌تر Restart یا Reboot agent پورت عمومی را برای همیشه می‌بست. اکنون BCC همان Plan بازبینی‌شده را با Apply امضاشدهٔ تازه دوباره اعمال می‌کند. روی سرورهای واقعی:
  - پس از Restart، Ready در ۱۲ تا ۱۴ ثانیه برگشت.
  - پس از Reboot سرور ایران، Ready در ۲۱ ثانیه برگشت.
- **Shared Transport:**
  - یک tenant از مسیر Plan بازبینی‌شده (`join_existing_tunnel_id`) به listener خارجِ یک تونل موجود، روی همان پورت، می‌پیوندد. پورت عمومی و هدف tenant جدا هستند.
  - کنار گذاشتن tenant فقط پورت و قانون خودش را حذف می‌کند.
- **رفع باگ جدی BCC:** پس از کنار گذاشتن یک tenant مدیریت‌شده، BCC دیگر هیچ تونلی را جلو نمی‌برد. این باگ رفع شده است.
- **کشف خودکار مسیر به‌طور پیش‌فرض خاموش است:**
  - پیش‌تر هر ۳۰ دقیقه روی همهٔ سرورها listener آزمایشی باز می‌کرد.
  - برای روشن کردن آن، `BAFT_BCC_DISCOVERY_PORTS` را روی BCC تنظیم کنید. کشف فقط روی همان پورت‌ها اجرا می‌شود.
- **پاک‌سازی رازها:** پیام‌های خطا و گزارش‌های agent پیش از ذخیره و نمایش پاک‌سازی (redact) می‌شوند.
- **رفع باگ‌های دیگر:**
  - تست اتصال هرگز نمی‌توانست FULL_DATA شود. رفع شد.
  - یک تونل Decommission‌شده ساخت تونل جدید روی همان سرور را مسدود می‌کرد. رفع شد.
  - بازیابی پس از crash و رسید گم‌شده اصلاح شد (#292، #293، #294).

### محدودیت‌های مؤثر در انتخاب نسخه

- **Restart و Reboot:** listener عمومی در پروسهٔ agent است. پس از Restart یا Reboot، پورت عمومی تا اعمال دوباره بسته می‌ماند (در اندازه‌گیری‌ها ۱۲ تا ۲۱ ثانیه) و اتصال‌های باز قطع می‌شوند.
- **جهش تأخیر هنگام تغییر tenant:** روی مسیر واقعی، یک اتصال طولانی مالک هنگام پیوستن و کنار رفتن tenant قطع نشد و داده‌اش سالم ماند. ولی بیشینهٔ تأخیر آن به ۰٫۶ تا ۰٫۷ ثانیه رسید (RTT عادی حدود ۰٫۲ ثانیه). علت آن هنوز اندازه‌گیری نشده است.
- **حالت امن میزبان:** برنامه‌ای را که دستی اجرا شده ولی هنوز پورت را باز نکرده، نمی‌بیند. برای همین Plan برای هر پورت تأیید صریح اپراتور می‌خواهد.
- **دامنهٔ آزمون روی سرورهای واقعی:**
  - همهٔ آزمون‌ها روی یک جفت سرور و یک شبکه انجام شده است.
  - 3X-UI روی سرور واقعی هنوز آزموده نشده است.
  - Reboot روی سرور واقعی یک بار آزموده شده است.
- **Uninstall:** پس از `baft uninstall --full`، در LAB واقعی این مسیرها باقی ماندند و باید دستی پاک شوند: `/etc/baft`، `/var/lib/baft`، `/var/lib/baft-agent`، `/usr/local/lib/baft` و `/usr/local/bin/baft-net`.
- **ارتقا و بازگشت:**
  - پایگاه دادهٔ BCC از v0.4.0 تغییر schema ندارد. با این حال پیش از ارتقا یک snapshot تأییدشده نگه دارید.
  - agentهای قدیمی تا ارتقا، تست اتصال را بدون TLS اجرا می‌کنند.

### نصب

برای نصب، فقط از assetهای امضاشدهٔ انتشار و مسیر installer استفاده کنید. این مسیر manifest، certificate، checksumها و revocation را در برابر ریشهٔ ثابت BAFT بررسی می‌کند. artifact `unsigned-release-candidate` را نصب نکنید.

شواهد و تصمیم‌ها: [HQ #67](https://github.com/zarkmakerburg/BAFT/issues/67).

## English

v0.5.0 is a research release qualified by reproducible LAB acceptance and, for the first time, by runs of the product path between one real server in Iran and one abroad over the real Internet. That evidence covers those servers, that network and the exact source commit. It does not establish availability or production readiness.

### Main changes

- **Guided, live tunnel creation**: the Command Center's "+ New tunnel" builds real tunnels in five steps (servers, service, connection test, review, deploy). It reports done only when the tunnel is active and BCC itself has verified the public port.
- **Connection test**: a signed path test between the two servers on chosen ports, with a speed estimate. When both agents support it, the probe flows run inside TLS 1.3 with a browser-like ClientHello and no SNI, so they carry no fixed signature on the wire.
- **Safe host mode** (opt-in, `--enable-host-ingress`): BAFT opens the public Iran port on ordinary servers.
  - It refuses a port held by another program, 3X-UI/Xray, nginx, HAProxy or Docker.
  - It opens only its own listener and rule in its own chain, and removes exactly those on decommission.
- **Restart and reboot recovery**: an agent restart or reboot used to close the public port for good. BCC now re-applies the same reviewed plan with a fresh signed Apply. On the real servers, Ready returned 12 to 14 s after an agent restart and 21 s after an Iran server reboot.
- **Shared transport**: a tenant joins an existing tunnel's foreign listener on the same port through the reviewed plan (`join_existing_tunnel_id`), with its own public port and target. Retiring the tenant removes only its own port and rule.
- **Fixed: BCC stopped advancing every tunnel after a managed tenant was retired.**
- **Automatic path discovery is off by default.** It used to open test listeners on every server every 30 minutes. To enable it, set `BAFT_BCC_DISCOVERY_PORTS` on BCC; discovery then runs only on those ports.
- **Secret redaction** of failure messages and agent reports before they are stored or shown.
- **Other fixes**: connection tests could never reach FULL_DATA; a decommissioned tunnel blocked new tunnels on the same server; crash and lost-receipt recovery (#292, #293, #294).

### Limits that matter when choosing this version

- **Restart and reboot**: the public listener lives in the agent process. After a restart or reboot, the public port stays closed until re-applied (12 to 21 s in the measurements), and open connections drop.
- **Latency spike during tenant changes**: on the real path, a long-lived owner connection stayed connected with intact data while a tenant joined and retired, but its maximum echo latency reached 0.6 to 0.7 s (normal RTT is about 0.2 s). The cause has not been measured yet.
- **Safe host mode**: it cannot see a program that was started by hand and has not yet bound the port. That is why the plan asks the operator to confirm each port explicitly.
- **Real-server test scope**: all runs used one pair of servers and one network. 3X-UI has not been tested on a real server, and a real-server reboot was tested once.
- **Uninstall**: in the real-hosts LAB, `baft uninstall --full` left these paths behind, to be removed by hand: `/etc/baft`, `/var/lib/baft`, `/var/lib/baft-agent`, `/usr/local/lib/baft` and `/usr/local/bin/baft-net`.
- **Upgrade and rollback**: the BCC database schema is unchanged since v0.4.0. Keep a verified snapshot before upgrading anyway. Older agents run connection tests without TLS until they are upgraded.

### Installing

Install only through the signed release assets and the installer path. It verifies the manifest, certificate, checksums and revocations against the pinned BAFT root. Do not install the `unsigned-release-candidate` artifact.

Evidence and decisions: [HQ #67](https://github.com/zarkmakerburg/BAFT/issues/67).
